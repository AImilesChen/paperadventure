Cloudflare's dashboard ZIP upload was used because this environment has no authorized Wrangler credentials. The deployable ZIP is `output/paper-adventure-preview.zip`; its unpacked contents are in `output/cloudflare-preview-upload/`. The Ahrefs exception was deployed as Cloudflare version `44bc9d85` on 2026-10-07.

The first static Worker, `paper-adventure-preview`, remains in the account without a custom domain. It serves `/` but lacks deep-link routing; do not link users to it. The apex `paperadventure.app`, `preview.paperadventure.app`, and temporary `preview-v2.paperadventure.app` domains all point to `paper-adventure-preview-v2`. The apex currently serves the static noindex preview, with `/` redirecting to `/en/`.

Before the Ahrefs exception, `robots.txt` returned 200 and disallowed all crawling; after that change the Codex in-app browser blocked direct navigation to `/robots.txt`, so the new live crawler result awaits an Ahrefs recheck. `/api/v1/health` returned 404. The React preview visibly renders in the Codex in-app browser. This is a static preview only: no backend API, D1, R2, Queue, Stripe, OpenAI, Resend, emails, payments, generated packs or downloads are connected. Rebuild and recreate the ZIP after frontend changes; the current ZIP is a snapshot of this deployment.

`production-worker.mjs` is the new Cloudflare Worker entry point. It serves `dist/client` through an `ASSETS` binding and handles `/api/v1/*`. The existing Sites preview adapter in `worker/index.js` is unchanged. `wrangler.production.template.jsonc` is a template, not a deployable configuration.

The owner registered **paperadventure.app** as the project domain. The template now sets `PUBLIC_ORIGIN` to `https://paperadventure.app` for future checkout-return and email-link URLs. HTTPS on the apex now serves only the static preview Worker; the production backend route, sender email domain, backend bindings and secrets remain unconfigured. Release flags stay off.

Implemented and locally tested:

- Four SKU purchase validation, server-side price/version lookup, a Stripe Checkout Session with an idempotency key, and a payment webhook that checks its HMAC signature, session ID, order ID, snapshot hash, USD subtotal and paid state before granting an entitlement. The final total is taken from Stripe after tax.
- Ready-pack entitlement only for a published version with A4/Letter player and guide records. Authenticated R2 file reads hash the actual bytes and compare them with the D1 SHA-256/byte count; they never use an order ID alone as a password.
- Adult email-link authentication with a one-use 15-minute challenge, a 7-day HttpOnly SameSite cookie, purchase listing and draft storage/deletion (`GET`, `PUT`, `DELETE /api/v1/my-draft`). Payment/file-ready notices have a retryable outbox and create a fresh access link after matching the Stripe customer email to the order's protected email hash. Email delivery is wired to the Resend REST API, but no sender domain or API credential is configured.
- Two short OpenAI proposals with a per-IP daily cap; paid custom generation through a Cloudflare Queue, strict JSON structure, five-stage chain checks and a second model-based semantic audit, separate player and adult PDF files (player checkpoints on separate pages), private R2 storage, usage records, per-request retry/failure state, a purchaser email on terminal generation failure, and a one-stage local revision that consumes allowance only when a new version is published.
- A free Celebration sample endpoint gated by `FREE_SAMPLE_ENABLED`, published packs, and private-file integrity checks. It remains off.
- Four versioned legal-page records must all be published in D1 before checkout can open. The Worker then serves those exact records to the site and stores their versions in the order snapshot. Verified purchasers can file order-linked issue or refund requests; a full Stripe refund webhook revokes file access. A scheduled handler clears expired login/rate-limit records and requeues abandoned jobs.

All flags in the template are **false**. The checked-in catalog remains a preview. No Stripe, OpenAI, Resend, D1, R2 or Queue service has been provisioned or connected. No real purchase, email, generation or download has been performed.

The owner confirmed Home household/Classroom one-teacher use and 12-month online re-download on 2026-10-08; the backend now snapshots that policy and sets ready access from verified payment, custom access from first qualified delivery. Verify it in the final consumer licence, notice and production data before sale. Have legal documents reviewed for the markets actually sold to. Do not flip `LEGAL_RELEASED` merely because a draft exists.
   The four supported-age/player limits in the Wrangler template are `0` on purpose. Replace them only with ranges supported by actual Home and Classroom play-testing; the numbers used in unit tests are mock fixtures, not product claims.
2. Play-test and approve the Celebration Home and Classroom PDFs separately. 3. Create D1, R2 and a Queue; copy and fill the Wrangler template in a local config.
