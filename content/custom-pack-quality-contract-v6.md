# Custom Pack Quality Contract v6

New creator-v3 orders and eligible same-order rebuilds snapshot `packQualityVersion: 8`. The paper layout remains version 4.

## Content before delivery

- Every ordering tile names an unfinished fictional action. Records and objects are not action steps.
- The four printed findings remain available to the player. Each story link must derive its consequence from those printed facts and explain how it supports the final action.
- The three final choices are complete natural-English actions. The selected action must achieve the approved goal.
- The ending names an observable result of that action and a character or community response. A generic claim that the result is visible is not a valid ending.

Generation instructions distinguish action tiles from record and code pieces. The mechanical ending check enforces complete sentences and rejects generic outcomes; the full-game audit judges whether the specific outcome actually fulfils the goal. An ending-only audit issue repairs only the closing paragraph, even if the provider labels it checkpoint 5.
The checkpoint audit receives candidate pieces without engine-supplied rule cards. An overlong final action may lose optional modifiers or articles, but never its verb, object or required preposition; otherwise it is returned for rewriting.
The printed ending starts with the checked final code and completed action. It does not repeat the opening's still-blocked premise; the success after the final action is an expected new event.

Independent printed-puzzle proof still establishes unique answers and result digits. The full-game editorial audit receives the actual printed pieces, story links and ending. One concrete defect blocks publication and identifies the affected checkpoint or closing; an unavailable audit also cannot publish a version-8 pack. Subjective style preferences are outside this blocking review.

## Repair and release

The generator repairs the affected blueprint context and retains earlier checked checkpoints when their contracts are unchanged. New purchases and paid same-order rebuilds have bounded calls. If those calls cannot produce a passing pack, the job stops with its saved work; a rebuild never replaces earlier downloadable PDFs until the complete story, both PDFs and stored bytes pass. The order API distinguishes a delivered version-8 content review from file availability under earlier quality versions.

Fixture tests prove gate behavior, not model reliability or family usability. Before broad delivery claims, run invented Home and Classroom real-provider scenarios across distinct mechanics, inspect both PDFs and complete a blind playthrough with the two printed files.
