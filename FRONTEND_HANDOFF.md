# Frontend handoff — 2026-10-07

The English-first preview is a static, noindex design prototype at https://preview.paperadventure.app/en/. The local source produces 30 route-specific, pre-rendered pages with distinct titles, descriptions, canonical URLs, social preview tags and WebPage structured data. The local build also includes a deny-all `robots.txt` and `X-Robots-Tag: noindex, nofollow`. No production sitemap or Search Console submission should be made while sales, downloadable packs and final legal text are pending. On 2026-10-07, the rebuilt ZIP was uploaded in the Codex in-app browser to the existing Cloudflare Worker `paper-adventure-preview-v2`; Cloudflare reported deployment `9a709e9d`. Live homepage and pricing deep-link checks showed the new route metadata and `noindex`, and the homepage loaded no GA4 or Clarity script.

Run `npm run build`, `npm run test:static`, `npm run test:sites`, and `npm run test:backend` before a frontend preview update. On Windows, `npm run package:preview` creates `output/paper-adventure-preview.zip` from the current `dist/client` tree. The ZIP is an upload artifact; rebuilding it does not change the live Cloudflare Worker. Verify the uploaded preview on desktop and a narrow mobile viewport, then check the homepage, catalog, theme detail, custom creator, pricing, legal pages, `robots.txt`, and a missing API route. The local 390 px catalog check showed no horizontal page overflow; a full remote device and performance audit remains for launch.

GA4 and Microsoft Clarity are wired behind three conditions: valid public site IDs, `VITE_ANALYTICS_RELEASED=true`, and a visitor's explicit choice. The choice UI offers decline/allow and a persistent privacy-choice entry point. No analytics vendor script is included or fetched in the current build, since the owner has not created the two site IDs and the final privacy notice is pending. Set the IDs in a deployment environment (see `.env.example`), test both consent choices and withdrawal, and review the event list in `src/analytics.js` before enabling the release flag. Events must never include story text, emails, or player details.

The owner selected `support@paperadventure.app` as the intended support address, but its mailbox/routing and sender domain are not yet configured. Do not present it as a working service contact until a test message is received and a reply can be sent. Use only the Codex in-app browser for any required web-based authorization; never allow a Git helper to open a desktop browser.
